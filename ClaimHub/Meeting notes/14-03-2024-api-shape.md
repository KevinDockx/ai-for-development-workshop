# API shape discussion, 14/03/2024

**Attendees:** Tom De Smet, Bram Jacobs, Anouk Willems, Pieter Claes

The controllers inherited from PolicyAdmin now mix routing, validation and mapping. Bram’s claims spike with route groups was shorter and kept related operations together. Anouk pointed out that it still needs authorization, validation and predictable error responses. Fewer lines do not remove those responsibilities.

For new HTTP work we will use Minimal APIs, grouped by business area. We are not opening a separate project to migrate existing controllers. When a controller changes for a real ticket, move the touched endpoint if that can be done without changing its contract. “When touched” means actual functional work, not drive-by conversion.

Pieter asked whether billing consumers must change routes. They do not. Route compatibility matters more than making every URL look alike during the migration.

Nobody volunteered to convert `PoliciesController` now, so it remains as it is.
